# M5 plan: the plant's voice

Scope: the `PlantChat` / `PlantChatiOS` slices, the Talk screen (`docs/DESIGN.md` section 6),
personalities, the generated home line, mood notifications, and the template fallback.

Out of scope: voice input and spoken replies (M5b), streaks, the tab bar, background
monitoring (M6), and streamed replies.

The work is split in two parts:

- **Part A:** the business layer and its unit tests. Everything runs with `swift test`.
- **Part B:** UI, platform clients, app wiring, integration tests, and docs.

## 1. Where things go

| Piece | Target / folder | Part |

| `PlantLanguageModelClient`, `PlantLanguageModelSession`, `PlantLanguageModelError`, `PlantNotificationClient` (protocols) | **PlantChat/Client** (new folder) | A |
| `FoundationModelsPlantLanguageModelClient`, `UserNotificationsPlantNotificationClient` | PlantChat/Client | B |

| Adapters, `.chat` route, notifier start | App target | B |

**Import rule.** `FoundationModels` and `UserNotifications` are imported only inside
`PlantChat/Client/`. This mirrors CoreBluetooth and SwiftData in `PlantShared/Client/`.
They stay in PlantChat because no other feature uses them yet.

The concrete FoundationModels client is marked `@available(macOS 26, *)`, so the package's
macOS 15 platform stays as it is. Tests never touch the concrete clients.

**Mood source.** PlantChat can't import PlantMonitor, so it defines a small `PlantMoodLoader`
(`load` + `subscribe`, mood only). The app passes an adapter of about 10 lines that wraps
the existing `LocalPlantHealthLoader`. The home line works the same way in the other
direction: the app adapts PlantChat's line loader to PlantMonitor's `PlantSpeechLoader`.

Both adapters only forward calls. This avoids moving `PlantHealth` and `PlantHealthLoader`
into PlantShared.

# Part A: business layer

## A1. The model seam

Uses the completion style from ARCHITECTURE.md 3.4.

```swift
@MainActor public protocol PlantLanguageModelClient {
    var isAvailable: Bool { get }
    func makeSession(instructions: String, canReadHistory: Bool) -> PlantLanguageModelSession
}

@MainActor public protocol PlantLanguageModelSession: AnyObject {
    typealias Result = Swift.Result<String, Error>
    /// Remembers earlier turns of the same session.
    func respond(to prompt: String, completion: @escaping (Result) -> Void)
}

public enum PlantLanguageModelError: Error, Equatable {
    case contextTooLong
    case generation
}
```

`PlantNotificationClient` has one method, `post(title: String, body: String)`.

## A2. Facts and prompts

These are deterministic.

- **`PlantVoiceFacts(mood:isSleeping:reading:)`.**
- **`LocalPlantVoiceFactsLoader(moodLoader:store:currentDate:)`**
  - Loads the mood.
  - Then takes the latest reading in the store from the last 24 h, or nil if there is none.
  - `subscribe` forwards to the mood loader.
  - Errors map to `.retrieval`.
- **`PlantVoicePrompt`**
  - `instructions(personality:plantName:)` says:
    - who the plant is
    - the personality's voice
    - "answer in 1–3 short sentences"
    - "only use numbers that appear in the facts or in a tool result; never guess a value;
      if you don't know, say so"
  - `facts(_:)` gives:
    - a plain description of the mood, e.g. "thirsty: the soil is getting dry, you'd like
      water soon"
    - each reading formatted with `PlantReadingFormatter`, leaving out nil values
    - "no readings yet" when there is no reading
    - "it's night and you're sleepy" when sleeping
  - `line(_:purpose:)` asks for one line of at most 12 words with no numbers, for the home
    bubble, a notification, or the chat greeting.
  - `history(_:)` writes the history summary as text, using the formatter.
  - `cleanLine(_:)`
    - Trims whitespace and surrounding quotes, and keeps the first line.
    - Returns nil when the result is empty, longer than 100 characters, or contains a digit.
    - The caller then uses the template. So home and notification text can never show an
      invented number.
- **`LocalPlantHistorySummaryLoader(store:currentDate:)`**
  - For `.day` (24 h) or `.week` (7 days): minimum, average, and maximum of each sensor,
    ignoring nil values, plus the reading count.
  - A store failure becomes `.retrieval`.
- **Template lines** live in `PlantChat.strings`: one per mood, a greeting, and the fallback
  reply.

## A3. Personalities

- **`PlantPersonality`**
  - Cases: `cheerful` (default), `dramatic`, `grumpyGrandma`, `chillSurfer`, `politeButler`.
  - Each has a voice description used in the instructions.
  - `PlantPersonalityViewModel` gives the localised label.
- **`PlantPersonalitySettings(defaults:)`**
  - `load()` returns the saved personality, or `.cheerful` when nothing valid is saved.
  - `save(_:)` stores the raw value under `plant.chat.personality`.
- **`DefaultsClient`**
  - Gains `set(_: String, forKey:)` and `retrieveString(forKey:)`. The different name keeps
    the existing `retrieve` calls unambiguous.
  - `UserDefaultsClient` and the PlantShared `DefaultsSpy` are updated.

## A4. Line and chat loaders

**`LanguageModelPlantVoiceLineLoader(client:personality:)`**

- `load(_ request: PlantVoiceLineRequest, completion:)`. The request holds facts and a
  purpose: `.home`, `.notification`, or `.greeting`.
- If the model is unavailable, it fails at once with `.unavailable` and creates no session.
- Otherwise it creates a fresh session without the history tool.
- It delivers the cleaned line, or `.invalidLine` when cleanup returns nil, or
  `.generation` on a client error.

**`LanguageModelPlantChatLoader(client:personality:)`**

- `isAvailable` comes from the client.
- `send(_ text: String, facts:, completion:)`
  - Creates one session on the first send, with the history tool, and reuses it after that.
  - Each turn's prompt is the current facts followed by the message.
- It starts a new session in these cases:
  - The personality changed since the session was created.
  - The session fails with `.contextTooLong`. The loader then retries once.
- `reset()` drops the session.

## A5. Chat view model

**`PlantChatViewModel(chatLoader:lineLoader:factsLoader:settings:plantName:actionHandler:)`**

`appear()` runs once (repeats are guarded):

1. Loads the facts and subscribes to updates. On every mood it emits `loadedMood` with the
   mood and its label (the face and the header follow it live).
2. Emits `loadedAvailability(Bool)`.
3. Greets with a `.greeting` line, or the template greeting when that fails.

`send(text)`:

- Ignores text that's empty after trimming, and ignores sends while a reply is pending.
- Adds your message, emits `loadedTyping(true)`, then adds the reply and emits
  `loadedTyping(false)`.
- When the reply fails, uses the template reply instead: the mood line plus
  "Right now: moisture 24%, …" built from the facts.

Other inputs:

- `select(_ personality:)` saves it, resets the chat loader, clears the messages, and greets
  again.
- `backTap()` sends `PlantChatAction.backTap`.

Observers:

- `loadedMessages([PlantChatMessageViewModel])` (text and sender)
- `loadedTyping`
- `loadedMood`
- `loadedAvailability`
- `loadedPersonality`

`personalities` lists the picker options.

## A6. Notifier

**`PlantMoodNotifier(factsLoader:lineLoader:notifications:defaults:plantName:currentDate:minimumInterval:)`**

- `start()` subscribes to facts updates and loads the facts.
- The first mood after launch is only recorded, with no notification.
- When the mood changes to anything other than happy, it posts a notification, but only
  when `currentDate − lastNotified ≥ minimumInterval`.
- The last notification date is saved in `DefaultsClient` under
  `plant.chat.notification.lastDate`, so the limit survives a relaunch.
- The interval uses the real clock (`Date.init`), not the simulated one. The app passes 1 h.
- Title: the plant name.
- Body: a `.notification` line in the current personality, or the template line for that
  mood.

## A7. Home speech bubble (PlantMonitor)

- **`PlantSpeechLoader`:** `load(mood:isSleeping:reading:completion:)` delivers
  `Result<String, Error>`.
- **`PlantMonitorViewModel`** gains a `speechLoader` and `loadedSpeech: Observer<String>`.
  - The key is mood + scene. When the key changes:
    1. The view model emits the template line (`scene.speech`) at once.
    2. It asks the loader.
    3. It emits the generated line only if the key is still the same. A failure keeps the
       template.
  - A new reading with the same key doesn't regenerate.
- **`loadedMood` is removed.** Only tests used it, and they now assert on the mood in
  `loadedScene`.

## A8. Package (Part A only)

Adds the `PlantChat` target (with `Resources`) and the `PlantChatTests` test target.

## A9. Unit tests

**PlantChatTests**

The base class `PlantChatXCTestCase` holds the factories and these doubles:

- `LanguageModelClientSpy` and `SessionSpy`: record `makeSession` calls and prompts, and
  complete on demand.
- `MoodLoaderStub`, `StoreSpy`, `DefaultsSpy`, `NotificationClientSpy`, and stubs for the
  line, chat, and facts loaders.

Tests cover:

- **`PlantVoicePrompt`:** instructions for every personality, facts text with nil values and
  with no reading, sleeping, history text, and every `cleanLine` case.
- **`PlantPersonalitySettings`:** the default, a saved value, an unknown raw value.
- **`LocalPlantVoiceFactsLoader`:** the retrieval window, latest reading or none, error
  mapping, subscribe forwarding, memory leaks.
- **`LocalPlantHistorySummaryLoader`:** the window per period, aggregates, nil values, empty
  history, error mapping, memory leaks.
- **Line loader:**
  - unavailable means no session
  - a session without history, using the personality's instructions
  - cleaned success, invalid line, client error
  - memory leaks
- **Chat loader:** session reuse, prompt contents, a personality change, the context retry
  happening once, reset, memory leaks.
- **`PlantMoodNotifier`:**
  - the first mood is silent
  - a problem notifies, happy doesn't, and an unchanged mood doesn't
  - the rate limit: inside and outside the interval, and across instances
  - the template fallback, and the title
- **`PlantChatViewModel`:** greeting and its fallback, the send flow, empty and pending sends
  ignored, the fallback reply, personality change, availability, live mood, back action.

**PlantMonitorTests**

- The speech behaviour from A7: template first, the generated line replaces it, failure
  keeps the template, a stale result is ignored, a scene change regenerates, the same key
  doesn't reload.
- The existing view model tests get a speech loader stub and drop `loadedMood`.

**PlantSharedTests**

- A string round-trip through `UserDefaultsClient`.

Run with `swift test --filter` on PlantChatTests, PlantMonitorTests, and PlantSharedTests.

# Part B: UI, clients, wiring, docs

## B1. Platform clients

**`FoundationModelsPlantLanguageModelClient(historyLoader:)`**

- `isAvailable` reads `SystemLanguageModel.default.availability == .available` on every call,
  so a model that finishes downloading is picked up without a restart.
- A session wraps `LanguageModelSession(tools:instructions:)` and calls `respond` in a `Task`.
- Error mapping: `exceededContextWindowSize` becomes `.contextTooLong`; any other error
  becomes `.generation`.
- With `canReadHistory`, it adds `PlantHistoryTool`:
  - One `@Generable` argument: the period, `day` or `week`.
  - It hops to the main actor, calls `PlantHistorySummaryLoader`, and returns
    `PlantVoicePrompt.history(...)`.
- `prewarm()` runs when the Talk screen opens.
- This is the only code without unit tests. All prompt text and tool output comes from
  tested code.

**`UserNotificationsPlantNotificationClient`**

- `post` asks for permission the first time it's needed, so the prompt appears when the
  plant first has a problem. It then adds an immediate request.
- It is the notification center delegate and returns `.banner` and `.sound`. Until M6 the
  app only runs in the foreground, so banners must show in the foreground.

## B2. Talk screen (PlantChatiOS, DESIGN.md section 6)

**Composer**

`PlantChatUIComposer.composed(chatLoader:lineLoader:factsLoader:settings:plantName:face:actionHandler:) -> PlantChatView<Face>`

The Sprout is embedded through a factory closure (ARCHITECTURE.md 5.4). The app passes
`PlantFaceUIComposer.composed`.

**Layout**

- **Header**
  - Left: a 44 pt round back button (`card`) that calls `backTap`. The system back button is
    hidden.
  - Next to it: the name (22 heavy) and the mood label (14 bold, `inkSecondary`).
  - Right: the personality picker, a 44 pt round `card` button with the sliders icon,
    opening a `Menu` with a checkmark on the current choice.
- **Sprout:** 200 × 233 pt (the 240 × 280 ratio), centered, fixed above the messages.
- **Messages**
  - A scroll view that scrolls to the newest message.
  - Plant bubbles: `card`, radius 20 / 20 / 20 / 6, max width 290, 16 bold, line spacing for
    ~1.35, 12 × 14 padding, 10 pt spacing.
  - Your bubbles: the screen's `ink` as background, with inverted text: `#1F2A24` with
    white text in light mode, `#EEF2F6` with `#1F2A24` text in dark mode. Radius
    20 / 20 / 6 / 20, max width 250.
  - A plant bubble showing "…" while a reply is pending.
- **Unavailable notice:** a small `card` row under the Sprout: "Sprout's voice needs Apple
  Intelligence. Replies are simple for now."
- **Bottom:** a text field with a round send button (`primary`), pinned above the keyboard.
  Send is disabled while the text is empty or a reply is pending.

**Styles**

- `PlantChatColor` follows the system: day tokens in light mode, night tokens in dark mode.
- `PlantChatFont` uses SF Pro Rounded.

## B3. App wiring

**Clients and loaders**

Creates the FoundationModels client (with a `LocalPlantHistorySummaryLoader` on the store,
using the simulated clock), `PlantPersonalitySettings`, and the facts, line, and chat
loaders.

**Adapters**

- `PlantHealthMoodLoaderAdapter`: PlantChat's `PlantMoodLoader`, wrapping `LocalPlantHealthLoader`.
- `PlantVoiceSpeechLoaderAdapter`: PlantMonitor's `PlantSpeechLoader`, wrapping the line loader.

**Notifier**

Creates `PlantMoodNotifier` with the UserNotifications client, the real clock, and a 1 h
interval, then calls `start()`.

**Navigation**

- `.talkTap` pushes `.chat`.
- `PlantChatAction.backTap` pops.

**Fallback check**

The simulator can use the Mac's model, so DEBUG builds accept the launch argument
`-PlantVoiceUnavailable`. It injects an unavailable client, which makes the fallback easy
to check.

## Notes

- **Real model checks happen on the iPhone.** Real model output, tool calling, and the
  notification permission can only be checked there.
- **Chat replies have no hard number check.** They rely on the instructions, the facts, and
  the history tool. Home lines and notifications contain no digits at all.
- **A personality change reaches the home bubble at the next mood or scene change**, not
  immediately.
